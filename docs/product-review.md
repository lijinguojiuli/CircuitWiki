# CircuitWiki 产品审查与优化

本次审查依据现有页面、内容索引与实际浏览器操作，不把设计判断当作用户调研结果。

## 发现的问题与已落地的调整

| 学习中的问题                     | 原因                                         | 本次调整                                                                                       |
| -------------------------------- | -------------------------------------------- | ---------------------------------------------------------------------------------------------- |
| 初次访问不容易判断从哪里开始     | 首页按功能和大类陈列，已有课程与规划课程并列 | 首屏说明受众、学习内容和起点；提供系统学习、公式查阅、动手验证三个任务入口，规划课程退出首页   |
| 目录很长，难以建立知识之间的关系 | 40 篇文章视觉权重相同，全部显示“核心”        | 六个学习阶段组织全局方向，保留教材章、节顺序；区别章节全览、知识专题和综合例题                 |
| 学完后缺少连续性                 | 没有阅读记录或完成状态                       | 记住最近阅读页，显式标记完成；首页继续学习、章节进度、目录标记同步                             |
| 搜索结果需要再找一次内容         | 只返回文章，按目录顺序截取                   | 按名称相关度排序，覆盖文章、教材小节、公式、工具；公式直接定位卡片，小节直接定位章节全览的段落 |
| 公式速查过长                     | 69 条公式只能连续滚动查找                    | 名称、符号、章节筛选；结果数量、清空操作、空结果恢复；保留所有公式的教材顺序与解释             |
| 知识页缺少当前阅读位置反馈       | 页内目录静态显示                             | 滚动时高亮当前小节；概念、公式、例题快捷入口；本章全览和本章公式互链                           |
| 工具与课程割裂                   | 计算器连续排列，没有任务引导                 | 按要解决的问题选择工具，每个工具返回相应学习专题；知识页提供相关工具入口                       |
| 手机端控件遮挡内容               | 主题切换固定悬浮在右下角                     | 小屏将外观设置放入目录菜单，保留浅色、深色、跟随系统                                           |

## 体验原则

- **让用户知道下一步**：新用户从第一章全览开始；回访用户可以继续最近阅读页，完成后推荐顺序中的下一篇未完成页。
- **保留学习的两种方式**：按章系统学习，也可以用搜索和公式手册即时查阅。
- **用信息层级表达结构**：阶段 → 教材章 → 全览/专题 → 页内概念、公式、例题。阶段不改变教材章号或文章顺序。
- **科学内容优先**：白纸黑字、清晰 SVG 和数学排版；不通过装饰动画增加阅读负担。保留响应式和深色模式。
- **不把浏览当成掌握**：打开页面只记录最近访问，完成状态必须由用户主动标记，并且可以撤销。

## 数据与工程边界

学习记录仅保存在当前浏览器的 `localStorage`，键为 `circuitwiki:study:v1`，包含有效文章标识、完成列表和最近阅读页。不同标签页同步；存储不可用时降级为当前访问的内存记录。无需账户、数据库或外部服务。清除浏览器数据会清除记录，不提供跨设备同步。

教材学习范围、戴维宁命名、非重点标记、等效电阻记号、电源符号、电路图与现有 MDX 正文保持原有约定。首页不显示跳过范围提示。旧课程规划地址保留可访问性。

公式的稳定锚点是 `formula-章号-节号-序号`，由现有公式目录的位置字段生成。新增公式时应保证位置唯一。全站搜索从统一的文章、教材小节、公式和工具元数据生成。

主要实现：`src/lib/learning.ts`、`src/lib/search.ts`、`src/lib/study-store.ts`，以及 `study-progress`、`formula-browser`、`reading-toc` 组件。新产品界面样式放在 `src/app/platform.css`，与原有科学图示样式分开。

## 验收

- 首次访问：首页 → 第一章全览 → 主动标记完成 → 首页继续下一篇。
- 回访：刷新后保留完成状态，学习路线和其他标签页同步进度。
- 查阅：键盘搜索公式 → 正确卡片；当前存在筛选时也能定位另一章公式。
- 公式：名称/符号/章节过滤后保持教材顺序，空结果可以一键恢复。
- 阅读：目录小节高亮随阅读变化，切换文章仍保留左侧目录滚动。
- 回归：全部学习页面、53 个小节锚点、公式、工具、深色模式和手机端布局。

截图位于 `docs/screenshots/product-*.png`，运行 `PLAYWRIGHT_CHANNEL=msedge node tests/capture-product.mjs` 可重新生成；其他系统可使用已安装的 Playwright Chromium。

## 下一阶段建议

1. 根据真实学习者反馈优化每章的学习目标与例题难度，建立基础练习 → 综合题的渐进练习库。
2. 将前置知识关系整理成可验证的数据，提供“这个知识点没懂，先补哪一节”的具体推荐。
3. 为学习记录提供本地导出/导入；出现明确的跨设备需求后再考虑账户同步。
4. 对题目错误类型提供针对性回顾入口，让完成状态逐步连接到可验证的学习结果。
