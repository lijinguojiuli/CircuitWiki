# 分阶段实施记录

## 产品分析（修改应用代码前完成）

- 依据：源代码、6类页面走查、桌面/手机快照、8次Lighthouse基线审计。
- 产物：《CircuitWiki 产品诊断报告》《产品架构与设计系统》。基线性能移动92–100、桌面91–100，其他三个类别均100。

## Phase 1：产品结构和布局

- 原因：教材目录、知识归属与概念关系需要分别表达；不同学习目标需要实际可用的入口。
- 文件：`lib/knowledge.ts`、`lib/paths.ts`、`lib/updates.ts`、`components/article-connections.tsx`、`knowledge-graph.tsx`、`app/knowledge`、`app/paths`、`app/graph`、首页、导航、移动目录、知识页、`tests/knowledge.test.ts`。
- 内容：六类知识树、可验证的前置关系及反向后续关系、三条学习路径、局部知识图/文本视图、真实维护日志、文章关系入口。
- 影响：保留现有URL、教材顺序、40篇MDX、69条公式与电路画法；知识图的建议前置关系不等于教材编排顺序。规划学科不计入当前课程。

## Phase 2：UI设计系统

- 原因：长时间阅读需要一致的字号、间距、焦点和内容块；新知识结构需要易理解的视觉表达。
- 文件：`components/primitives.tsx`、`app/design-system.css`、根布局、MDX组件映射与知识关系组件。
- 内容：语义变量、Button/LinkButton/Card/Tag/CodeBlock、知识树/路径/图谱布局、右侧关系区、小屏文本视图、正文16px与辅助文字12px规范；沿用Formula/Diagram/Alert科学组件。
- 影响：样式与布局调整；不改科学正文、计算函数和原教材目录。旧UI样式逐步迁移，未进行高风险整库重写。

## Phase 3：核心学习功能

- 原因：最近一页和完成列表不足以支持长期积累，搜索需要完整的发现视图。
- 文件：`lib/study-data.ts`、`study-store.ts`、`search.ts`、`assistant-contract.ts`；阅读工具、个人学习、完整搜索组件；`app/me`、`app/search`；文章、首页和导航；数据与浏览器测试。
- 内容：v1记录兼容至v2，收藏、历史、最远阅读位置、当前页阅读进度、本地导出与合并导入、搜索类型/分类过滤与分页；预留有出处的AI上下文契约。
- 影响：已有完成数据保留；无账户/数据库/模型调用；导入不清空现有记录。修正RL页面推荐RC工具的语义错误，仅推荐真正适用的计算器。

## Phase 4：SEO、性能与验收

- 原因：基础Lighthouse分数已较好，但canonical、社交分享与结构化知识信息缺失；新增界面需要验证性能没有退化。
- 文件：`lib/seo.ts`、各路由metadata、`app/sitemap.ts`、`robots.ts`、`opengraph-image.tsx`、`structured-data.tsx`、SEO浏览器验证与性能报告。
- 内容：每页独立规范地址与描述、Open Graph/Twitter分享、站点地图、知识资源与面包屑JSON-LD；个人页和搜索页不索引；同条件移动/桌面Lighthouse复测。
- 影响：知识URL和正文保持；只扩展SEO输出与性能加载方式。实际分数、测试结果和限制以最终验收报告为准，不宣称实验室结果代表所有用户设备。
